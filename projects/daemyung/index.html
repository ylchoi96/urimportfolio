Family Sale

A private, time-limited sale for Daemyung employees. I designed the experience from the entry screen onward and built the parts the platform didn’t provide: a code-gated entry, scheduled product drops, and category tabs.

Role
UI/UX design, event page design, front-end development
Platform
Cafe24 (custom HTML/CSS/JavaScript on top of the theme)
Scope
Intro, event landing, category tabs, timed releases, notices
Company
Q&B International, online team

Overview

The sale ran for a short window and only for employees. The journey had to go from a closed entry point to a landing page, through two product categories, and into purchase, with some products only becoming available at set times.

Problem

Traffic peaked hard at each release, and products went live at different times. People needed to know at a glance what they could buy now, what was coming next, and how to get in without friction.

1. Access code

A closed door that is easy to open.

The intro screen sets the tone of the event and asks for a single access code before anything else loads. Invalid codes get a clear message so employees can retry without contacting support.

2. Event landing

The schedule comes first.

The landing page puts release times and categories above the fold, so visitors understand the sale before they start browsing.

3. Timed releases

Products unlock on schedule.

Cafe24 has no built-in way to reveal product groups at set times on one page. I wrote a script that checks the time and switches each product area between “opens at” and “on sale”. Drag the slider to see how it behaves.

// Simplified version of the release logic
const RELEASES = [
  { selector: '.drop-11', opensAt: { h: 11, m: 0 } },
  { selector: '.drop-15', opensAt: { h: 15, m: 0 } },
];

function applyReleases(now = new Date()) {
  const minutes = now.getHours() * 60 + now.getMinutes();
  RELEASES.forEach(({ selector, opensAt }) => {
    const isOpen = minutes >= opensAt.h * 60 + opensAt.m;
    document.querySelectorAll(selector).forEach((el) => {
      el.classList.toggle('is-open', isOpen);
      el.classList.toggle('is-locked', !isOpen);
    });
  });
}

applyReleases();
setInterval(applyReleases, 30 * 1000); // re-check without a page reload

Simplified for readability; the production script ran inside the Cafe24 theme.

4. Category tabs

Two brands, one page.

Daemyung and Beauty products sit under separate tabs, so people can switch categories without leaving the event page or losing their place in the schedule.

5. Service notices

Saying what’s happening during peaks.

At each release the site was busy. Clear notices told people what to expect, such as slower loading or sold-out items, which kept them from repeatedly refreshing or leaving.

Takeaways

What this project shows.

Designing for a time window

The layout was built around the schedule, not just the catalogue, because timing drove every decision a shopper made.

Extending the platform

Where Cafe24 stopped, I filled the gap with targeted JavaScript instead of rebuilding standard commerce pages.

Clarity under load

Plain notices and visible states mattered most when traffic was highest.
